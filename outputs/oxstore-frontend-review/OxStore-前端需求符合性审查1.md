# OxStore 前端需求符合性审查

## 1. 审查信息

| 项目 | 内容 |
| --- | --- |
| 审查依据 | [需求规格说明书 V1](https://github.com/Wen5555/OxStore/wiki/%E9%9C%80%E6%B1%82%E8%A7%84%E6%A0%BC%E8%AF%B4%E6%98%8E%E4%B9%A6V1) |
| 审查范围 | 买家需求 B-001～B-007、卖家需求 S-001～S-012 的前端页面、交互及 API 调用 |
| 源码版本 | `main` 分支，`6a98bab`，2026-10-06 |
| 审查日期 | 2026-10-06 |
| 审查方法 | 前端源码核对、Playwright 模拟 API 测试、TypeScript/Vite 构建 |

本报告评价前端实现。后端业务规则、数据库约束、鉴权安全、并发、持久化和真实部署效果不因前端测试通过而视为通过。

## 2. 总体结论

前端已实现买家商品浏览、购买意向提交、口令自助服务，以及卖家登录、商品管理、意向队列、交易处理和历史记录等主要页面。此前发现的商品描述校验、冻结状态说明、队列提交时间和历史商品字段差距已修正。

**审查结论：前端主要功能基本符合，仍有入口可达性和真实后端联调方面的限制；不能据此认定整个系统已完成需求验收。**

## 3. 买家端需求核对

| 编号 | 需求 | 结论 | 核对说明 |
| --- | --- | --- | --- |
| B-001 | 查看在售商品 | 符合 | 展示商品名称、描述、主图、价格及在售状态，提供意向提交表单。见 [ProductPage.tsx](../../frontend/src/pages/buyer/ProductPage.tsx)。 |
| B-002 | 查看冻结商品 | 符合（前端展示） | 冻结时仍展示商品信息并隐藏提交入口；根据冻结来源区分交易中提示和手动冻结提示。 |
| B-003 | 查看无商品提示 | 符合 | 无当前商品时显示“目前没有正在出售的商品”，不再展示其他页面操作。 |
| B-004 | 提交购买意向 | 符合（前端流程） | 校验姓名非空白和手机号 11 位；提交成功展示口令码及排位。商品状态和服务端字段校验未在前端测试中证明。 |
| B-005 | 凭口令码查询进度 | 部分符合 | `/intent` 页面支持手动输入口令，查询结果显示本人状态和排位，不展示其他买家或完整队列。**无商品提示页不显示查询按钮**，此时需直接访问 `/intent`，查询入口发现性不足；这是为满足 B-003“无其他内容”所作的界面取舍。 |
| B-006 | 凭口令码修改信息 | 符合（前端流程） | 仅排队状态显示修改操作；允许修改姓名或电话，提交后重新查询。队列顺序由服务端维护。 |
| B-007 | 凭口令码撤销意向 | 前端流程符合，终态查询需按规格确认 | 排队状态提供撤销确认；成功后当前页面显示“已撤销”并隐藏操作。现有后端会使终态口令失效，因此刷新后不能凭原口令重新查询；规格未明确要求撤销后仍可重复查询。 |

## 4. 卖家端需求核对

| 编号 | 需求 | 结论 | 核对说明 |
| --- | --- | --- | --- |
| S-001 | 卖家登录 | 符合（前端流程） | 提供登录表单，成功后保存 JWT 并进入后台。服务端鉴权仍需由后端验证。 |
| S-002 | 修改密码 | 符合（前端校验） | 要求原密码、新密码和确认密码；新密码至少 8 位并包含字母、数字和特殊符号。密码校验和持久化依赖后端。 |
| S-003 | 发布商品 | 符合（前端校验） | 名称、描述、价格和图片均必填；描述不能全空白；价格须大于 0 且最多两位小数；图片限制 JPG/PNG、5 MB。实际图片内容类型和服务端业务状态须由后端校验。见 [PublishProductPage.tsx](../../frontend/src/pages/admin/PublishProductPage.tsx)。 |
| S-004 | 查看当前商品 | 符合（前端展示） | 展示商品信息、状态、发布时间、状态更新时间、售出时间；冻结时显示冻结来源。见 [CurrentProductPage.tsx](../../frontend/src/pages/admin/CurrentProductPage.tsx)。 |
| S-005 | 手动冻结商品 | 符合（前端入口） | 在在售或恢复在售状态显示冻结操作，并要求确认；是否有交易中意向由后端校验。 |
| S-006 | 手动解冻商品 | 符合（前端入口） | 仅手动冻结时显示解冻操作；交易冻结时不提供解冻入口。服务端拒绝非法操作尚未在本次前端测试中验证。 |
| S-007 | 查看意向队列 | 符合（前端展示） | 队列展示姓名、电话、提交时间、状态和位置，并提供刷新。见 [IntentQueuePage.tsx](../../frontend/src/pages/admin/IntentQueuePage.tsx)。 |
| S-008 | 选择队首开始交易 | 符合（前端流程） | 队列非空且没有交易中意向时，提供开始处理队首操作；成功后重新请求队列。队首及并发约束由服务端保证。 |
| S-009 | 确认交易成功 | 符合（前端流程） | 使用当前 `currentTradeAttemptId` 确认成功，完成后刷新队列；商品下架及其他意向状态需后端验证。 |
| S-010 | 确认交易失败 | 符合（前端流程） | 提供失败后重新排队或放弃，并在操作前二次确认；自动递补和商品状态变更由后端处理。 |
| S-011 | 查看历史商品 | 符合（前端展示） | 历史列表展示主图、名称、描述、价格、交易结果、发布时间和交易时间，并支持分页。排序正确性依赖接口返回顺序。见 [ProductHistoryPage.tsx](../../frontend/src/pages/admin/ProductHistoryPage.tsx)。 |
| S-012 | 查看历史意向 | 符合（前端展示） | 商品详情展示相关意向的姓名、电话、状态、首次提交时间和最近处理时间；完整记录页另展示交易尝试与商品状态事件。记录完整性依赖后端数据。 |

## 5. 统一交互与边界

- 前端通过统一 Axios 请求层调用 `/api`，附加卖家 JWT、设置请求超时，并处理 API 错误提示及 401 登录跳转；客户端路由守卫不能替代服务端鉴权。见 [request.ts](../../frontend/src/api/request.ts) 和 [App.tsx](../../frontend/src/App.tsx)。
- 卖家队列成功/失败确认携带当前交易尝试编号；队列操作后重新拉取数据，页面提供手动刷新，不属于自动轮询。
- 前端代码不能证明真实后端是否正确执行口令校验、终态口令失效、自动递补、原子事务、并发约束及数据持久化。
- 商品详情及历史记录中的数据字段由服务端接口提供；前端展示完整不代表后端已有数据均完整。

| 验证 | 结果 | 范围与限制 |

| Playwright | 3 条通过 | 买家提交后手动输入口令查询；卖家登录、开始队首交易并确认成功；商品描述必填和非空白校验。测试通过路由模拟 API，不连接真实后端或数据库。测试文件：[buyer-seller-flows.spec.ts](../../frontend/e2e/buyer-seller-flows.spec.ts)。 |

## 7. 待确认事项

1. B-005 查询入口：为严格满足 B-003，无商品提示页不展示查询按钮；持有口令的买家需要直接访问 `/intent`。如验收要求入口必须可见，需要调整 B-003 与 B-005 的交互口径。
2. B-007 撤销后查询：当前撤销成功后页面即时显示“已撤销”，但终态口令在后端失效。若要求刷新后仍查询到撤销状态，需要由需求方确认口令失效策略，并协调后端修改。
