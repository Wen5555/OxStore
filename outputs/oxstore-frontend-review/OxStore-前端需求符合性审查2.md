## 2. 总体结论

前端已具备 V2 的主要买家流程（顾客注册登录、商品浏览/二级筛选/搜索、详情、多图、提交意向、终态订单历史）及卖家流程（商品发布与有限编辑、上下架、商品队列与交易、顾客列表及顾客购买历史）；旧口令码流程不再作为前端入口提供。

**审查结论：前端主要功能部分符合；S-012 卖家历史意向查看未闭环，另有若干行为需真实服务端联调确认。** B-008 的下架详情显示问题已有前端拦截，且通过新增回归测试；这不代替服务端拒绝下架详情的校验。当前后端契约未提供卖家终态意向历史查询接口，前端无法仅靠页面代码可靠实现 S-012。

## 3. 买家需求核对

| 编号 | 需求 | 结论 | 前端核对说明 |
| --- | --- | --- | --- |
| B-001 | 顾客注册 | 符合（前端表单） | 包含用户名、密码、电话必填和默认地点选填；客户端检查必填及用户名/电话/地点长度、注册密码 8～64 位。用户名唯一性、哈希和注册成功持久化由服务端负责。见 [BuyerAuthPage.tsx](../../frontend/src/pages/buyer/BuyerAuthPage.tsx)。 |
| B-002 | 顾客登录 | 符合（前端流程） | 使用用户名和密码调用顾客登录 API，成功后保存顾客令牌；电话不是登录凭证。服务端凭证验证未由模拟前端测试证明。 |
| B-003 | 浏览在售商品 | 符合（界面/API 调用） | 匿名可打开列表；卡片展示名称、价格、主图、类目，不显示描述摘要或库存；无主图时用占位图。列表只含在售商品须由 API 保证。见 [ProductListPage.tsx](../../frontend/src/pages/buyer/ProductListPage.tsx)。 |
| B-004 | 按二级类目筛选 | 符合（界面/API 调用） | 加载类目树，筛选器只列出二级类目，选择后带 `category2Id` 重新请求。筛选结果正确性依赖服务端。 |
| B-005 | 关键词搜索 | 部分符合（服务端待验证） | 前端提供名称/描述关键词输入并以 `q` 请求商品列表；搜索先剥标签、匹配描述纯文本且不匹配类目的语义由服务端实现，当前 E2E 未验证。 |
| B-006 | 查看在售商品详情 | 符合（前端流程） | 显示库存、类目、商品图片和富文本描述；图片按返回顺序可预览，空描述隐藏描述区域；在售且 `canPurchase` 时显示购买入口。富文本危险内容过滤依赖服务端清洗。见 [ProductDetailPage.tsx](../../frontend/src/pages/buyer/ProductDetailPage.tsx)。 |
| B-007 | 直链查看冻结商品 | 符合（前端流程） | `FROZEN` 详情以只读提示呈现，隐藏购买入口，仍可查看图片。是否允许直链并从列表/搜索排除冻结商品依赖服务端。 |
| B-008 | 打开已下架商品详情 | 符合（前端防护；需服务端保障） | 页面在渲染前拦截 `OFFLINE`，显示不可查看空态；即使 API 返回下架商品成功数据也不展示商品信息。后端也应拒绝下架商品详情请求。Playwright 对成功返回 `OFFLINE` 的异常响应有回归测试。 |
| B-009 | 提交购买意向 | 符合（前端流程） | 未登录点击提交跳转登录；仅在状态为 `ONLINE` 且 `canPurchase` 时允许提交；不提供多件数量及口令码输入。未登录拒绝、商品实时状态校验和固定数量仍须服务端落实。 |
| B-010 | 查看历史订单 | 符合（界面/API 调用） | 登录后可进入历史页，展示商品名、下单时间、成功/失败及交易时间，支持分页。本人数据隔离、终态过滤、倒序及快照由服务端负责。见 [BuyerHistoryPage.tsx](../../frontend/src/pages/buyer/BuyerHistoryPage.tsx)。 |
| B-011 | 未登录访问历史 | 符合（前端路由） | 历史路由受顾客令牌守卫保护，未登录会被引导至登录页。API 仍需服务端鉴权。 |

## 4. 卖家需求核对

| 编号 | 需求 | 结论 | 前端核对说明 |
| --- | --- | --- | --- |
| S-001 | 卖家登录 | 符合（前端流程） | 提供卖家登录页，受保护的后台路由检查卖家令牌。服务端认证与授权需独立验收。 |
| S-002 | 修改卖家密码 | 符合（前端校验/流程） | 需要当前密码、新密码和确认密码；前端要求新密码至少 8 位、包含字母/数字/特殊符号。旧密码验证与哈希更新由服务端执行。见 [ChangePasswordPage.tsx](../../frontend/src/pages/admin/ChangePasswordPage.tsx)。 |
| S-003 | 发布商品 | 符合（前端表单） | 名称、价格、二级类目和库存必填；描述、商品图选填；库存可为 0；图片客户端限制 JPG/PNG、单张 5MB、最多 9 张；富文本编辑支持基础文本格式、列表和插图。真实文件内容校验、清洗与库存初始状态依赖服务端。见 [PublishProductPage.tsx](../../frontend/src/pages/admin/PublishProductPage.tsx)。 |
| S-004 | 有限编辑 | 符合（前端入口） | 编辑页仅开放库存与二级类目，并说明名称、价格、描述和图片不可原地修改。库存补充后是否仍保持下架依赖服务端。见 [ProductEditPage.tsx](../../frontend/src/pages/admin/ProductEditPage.tsx)。 |
| S-005 | 手动上架 | 符合（前端入口） | 下架商品在库存大于 0 时可确认上架；库存为 0 时按钮禁用。合法状态迁移由服务端校验。 |
| S-006 | 手动下架 | 符合（前端入口） | 在售商品可确认下架，界面说明队列意向将作废；无交易中意向的前置条件及队列作废结果依赖服务端。 |
| S-007 | 查看商品列表与状态 | 符合（前端展示） | 管理页展示多商品名称、价格、库存、二级类目、状态，支持分页。 |
| S-008 | 查看某商品意向队列 | 部分符合（顺序依赖服务端） | 按商品请求分页队列，展示排队及交易中意向；位置和 FIFO 顺序直接使用接口返回结果。实际顺序、各商品隔离性需真实联调。见 [ProductIntentQueuePage.tsx](../../frontend/src/pages/admin/ProductIntentQueuePage.tsx)。 |
| S-009 | 对队首发起交易 | 符合（前端操作流程） | 仅第一页、存在排队意向且无交易中意向时显示开始按钮，操作当前返回的队首。队首正确性和并发约束由服务端保证。 |
| S-010 | 确认交易成功 | 符合（前端操作流程） | 对当前交易中意向提供成功操作，完成后刷新队列。扣库存、自动下架及终态记录依赖服务端。 |
| S-011 | 确认交易失败 | 符合（前端操作流程） | 支持失败后重新排队或作废，并有二次确认；重排规则及失败历史由服务端落实。 |
| S-012 | 查看历史商品/意向 | 部分符合；意向历史缺失 | 商品管理可浏览商品及状态；但没有卖家终态意向历史页面或 API 调用。当前后端意向接口只提供活动队列和交易操作，没有查询 `SUCCESS`/`FAILED` 意向历史的接口。详见 F-01。 |
| S-013 | 查看全部顾客 | 符合（界面/API 调用） | 顾客列表显示用户名、电话、地点（空值显示“未设置”）、注册时间和购买历史入口，支持分页。是否包括所有顾客及按注册时间倒序依赖服务端。见 [CustomersPage.tsx](../../frontend/src/pages/admin/CustomersPage.tsx)。 |
| S-014 | 查看顾客购买历史 | 符合（界面/API 调用） | 可从顾客列表进入只读历史，展示快照商品名、下单时间、结果、交易时间并分页。终态范围、排序和历史快照由服务端保证。见 [CustomerHistoryPage.tsx](../../frontend/src/pages/admin/CustomerHistoryPage.tsx)。 |
