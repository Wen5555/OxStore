## 二、发现并已修复的问题

| 问题 | 实际复现 | 修正和回归 |
| --- | --- | --- |
| 交易结果 CHECK 存在 NULL 漏洞 | 直接向 MySQL 写入“finished_at 非空、result 为空”的记录，被错误接受；SQL CHECK 的 UNKNOWN 不能当作拒绝 | 新库和 V2 显式要求结束结果非空、失败动作非空；新增 V3 供已执行旧版 V2 的实例使用。6 类非法记录均被拒绝，4 类合法记录通过 |
| V2 前置拦截后无法正常重试 | 交易中意向被正确拦截，但 guard 过程留在数据库；结束交易后重试报过程已存在 | 重建辅助 guard 前先清理该过程；重新检查全部前置条件。拦截时尚未改表，结束交易后迁移成功；已迁移库再次执行仍被明确拒绝 |
| 单张主图限制未在服务端落实 | 同一 multipart 请求发送两个 `image` 部分，原接口返回 200 并取第一张 | Controller 接收图片列表并检查恰好一张，超过一张在写文件/商品前返回 400；原单张请求契约保持兼容 |

本轮涉及文件：`backend/src/main/resources/db/schema.sql`、`db/migrations/V2__queue_history.sql`、新增 `V3__trade_attempt_completion_check.sql`、`controller/admin/AdminProductController.java`、新增 `AdminProductControllerTest.java`、`README.md`。

**已有 V2 实例注意：**代码包更新不会自动升级数据库约束；新库与修订后的 V2 已有严格约束，已执行旧版 V2 的实例须另行在备份和副本演练后执行 V3。本次未替用户对任何现有库执行升级。

## 三、实际通过的验证

| 范围 | 覆盖结果 |
| --- | --- |
| 多人重排 | A/B/C 排队，A 失败后 B 自动交易、C 在 A 前；A 首次提交时间不变，失败选择与处理时间可读取 |
| 单人连续交易 | 同一意向连续两次失败后成功，保留三次尝试；恢复在售与再次冻结分别记录；旧尝试确认返回 409 |
| 在售失败记录 | 最后一人 DISCARD 后商品保持 RESTORED_ONLINE，后台记录仍包含 FAILED 意向及失败处理信息；非 SOLD 商品仍不能进入原历史详情 |
| 买家自助与权限 | 修改非 1 开头的合法 11 位号码成功；空号码/空修改拒绝；撤销退出队列、旧码失效；错误码不泄露个人信息；记录接口未登录 401、不存在商品 404 |
| 交易中限制 | 买家不能修改/撤销交易中意向，卖家不能手动解除交易冻结；缺少确认尝试 ID 返回 400 |
| 并发提交与确认 | 12 个并发提交不丢失；另有 100 个提交取样，队列人数正确；成功/失败同时确认只有一个成功，同一尝试不同时留下成功和失败 |
| 双开始交易 | 两个开始交易请求重叠时只允许一个成功；只存在一条交易中意向和一条对应交易尝试 |
| 真实锁等待 | 先由独立 MySQL 连接占住商品行锁，卖家开始请求等待；买家撤销完成后，卖家请求返回 409，不重新激活被撤销意向 |
| 全事务回滚 | 通过隔离库触发器分别使事件/交易尝试写入失败；手动冻结、开始交易、失败重排均不留下半完成状态或部分历史，移除故障后可继续执行 |
| 状态事件 | 多次手动冻结/解冻逐次留存；失败后递补保存恢复和再次冻结两个事件；非法操作不新增事件 |
| 新库与旧库迁移 | 新库可建表；有交易中意向的旧库在改表前被拒绝；升级按提交时间与 ID 稳定回填序号，原行/状态/联系方式/时间值保留，不伪造历史 |
| 旧有效口令兼容 | 迁移后 token_lookup 为空的旧有效口令仍可查询；旧数据不完整标记正确；迁移后开始/成功交易可执行，成功后旧码失效 |
| 数据库约束 | 完成但无结果、失败无动作、成功带失败动作、未结束但有结果、未知结果、结束早于开始均拒绝；重复未结束尝试拒绝；合法成功/失败/未结束记录可保存 |
| 图片与发布 | 双图、缺图、假文件头、PNG 内容伪装 JPG、超过 5MB 均返回 400；有效的恰好 5MiB PNG 可发布；重复发布 409，失败图片被清理，无新增孤儿文件 |

## 四、性能取样与未覆盖边界

在本机独立环境，**100 个有效新口令**下，10 次有效口令查询的最大耗时约 **0.075 秒**，错误码查询约 **0.007 秒**；有效 5MiB 图片发布约 **0.085 秒**。这些是指定工作量的取样，不能外推为所有 API、历史数据规模或目标服务器都满足时限。旧有效口令的 BCrypt 兼容扫描在本轮只验证了功能，未证明大量旧码时仍满足 2 秒。

以下仍需后续验证，不归入本次“通过”：

- 完整 Compose 镜像构建、Java 17 运行环境以及正式目标服务器的部署验证。
- 前端页面、按钮禁用、文案、端到端 UI 与页面加载时间；目前队列/历史页面仍是占位状态。
- 大规模历史列表/详情性能、持续负载及所有 API 的时限；当前历史列表仍为内存分页。
- 已售商品裸图片 URL 是否属于买家禁止访问范围，需要明确需求口径；本次保留现有图片访问行为。
