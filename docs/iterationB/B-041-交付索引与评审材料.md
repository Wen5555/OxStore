## 4. 技术变更记录

### 4.1 数据

- 新增 9 张表：订单与明细快照、收藏及操作代次、购物车及删行墓碑、结算确认及明细、幂等回执；3 个触发器（订单守卫、明细快照不可变、售卖模式不可变）。
- `product.stock` 由 `INT` 改为规范十进制 `LONGTEXT`，库存、数量、总额无 int/long/JS 安全整数上限；新增 `product.offline_reason`（`AUTO_ZERO`/`MANUAL`）。
- 一口价旧意向加关闭标记（`legacy_closed_at`/`legacy_close_reason`），V8 关闭并解冻，原状态和快照不变。

### 4.2 旧路径的替换

| 旧能力 | 现在 |
|---|---|
| 一口价提交购买意向、队列、冻结、成功/失败、重新排队 | 一口价已关闭，调用返回 409/40917；新购买必须先加购物车，经确认建一张多商品整单 |
| 旧意向记录 | 只读归档：`GET /api/me/legacy-intents`、`/api/admin/legacy-intents`；原状态与快照保留，不转成新订单 |
| 旧 `order-history` | 保留为兼容的只读历史，不混入新五态订单；新入口 `/api/me/orders` |
| 库存 | 下单直接扣减，完成不再扣，取消按快照回补一次；人工改库存与回补叠加 |
| 下架 | 库存为 0 自动下架（`AUTO_ZERO`），人工下架（`MANUAL`）；回补只对 `AUTO_ZERO` 且回补后大于 0 的商品恢复在售 |

### 4.3 新接口（按契约冻结的目录）

收藏 F01～F04，购物车 C01～C05，结算确认 Q01，下单 Q02，客户订单 O01～O03，商家订单 A01～A04，转收藏 M01，旧意向归档 L01/L02。新增业务错误码 40004、40005、40405、40909～40917、50001（见 B-000 §12）。

### 4.4 拍卖兼容

拍卖仍是独立既有能力，沿用原锁和收尾：`AuctionSettlementService` 与 `TradeServiceImpl` 的中标成功/失败路径保留；购物车、收藏、结算对拍卖商品返回既有 40908/409。已验证：升级后拍卖商品、场次、出价、提醒不变；拍卖商品不能进入购物车；容器里出价与快照正常。**拍卖结拍、SSE、提醒的完整回归是 R2 的 B-035，尚无证据。**
