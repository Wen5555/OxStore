## 2. 数值方案（B-003）

- 库存、数量、订单总额、行金额以规范十进制字符串（LONGTEXT）落库，没有 int/long、JS 安全整数或列宽上限；格式由 CHECK 保证（拒绝负号、小数点、前导零、空串、空白、科学计数法、尾随换行）。
- 单价快照沿用 `DECIMAL(10,2)`（商品单价列本身的精度），不承载总额。
- JPA 侧用 `BigIntegerStringConverter`（数量/库存）和 `MoneyStringConverter`（两位小数金额）。LONGTEXT 不能在 SQL 里做数值比较或排序，运算必须在持锁后用 `BigInteger`/`BigDecimal` 完成。
- 传输沿用 B-000 §4.1：新增接口数量/库存/金额用字符串。

## 3. 需要其他成员处理的交接点

1. **`Product.stock` 在实体里仍是 `int`（R1 B-006）。** 数据库列已是 LONGTEXT，当前仍能读写小数值，但超过 int 的值会读取失败。B-006 须把实体字段改为 `BigInteger` + `BigIntegerStringConverter`，同轮升级 `ProductDetailResponse`、`ProductServiceImpl` 和管理端请求 DTO（B-000 §4.1）。R5 没有改这些文件，以免与 R1 冲突。
2. **`offline_reason` 的取值与清除（R1 B-006）。** 实体只映射了字段与 getter。`Product.putOnline/takeOffline/updateInventoryAndCategory/markTradeSucceeded` 目前不维护它；数据库刻意没有加 “状态与原因联动” 的 CHECK，避免现有代码在 V7 后写入失败。B-006 实现后再决定是否加联动约束。
3. **状态流转与取消规则（R1 B-013/B-014）。** `ShopOrder.applyStatus/markCancelled` 只做持久化；数据库只兜底终态不可变和取消元数据成对，跳步/回退/权限由状态机判定。
4. **锁顺序（R1/R4）。** Repository 已提供 `customer → receipt → order → product → cart_item → favorite` 所需的 `FOR UPDATE` 查询，商品按 ID 升序加锁的批量方法由 R1 在 B-011 按需提出，R5 集中补到 `ProductRepository`。
5. **车行删除须同事务写墓碑（R4 B-008/B-009/B-025）。** `CartItemTombstone` 无外键；`AUTO_INCREMENT` 在 MySQL 8 持久，行 ID 不复用。
6. **旧意向归档（R4 B-016）。** `PurchaseIntent.getLegacyClosedAt()/isLegacyClosed()`、`TradeAttempt.getLegacyClosedAt()` 为只读映射（`insertable=false, updatable=false`）。

## 4. 请 R1 在契约评审时确认

- **`checkout_confirmation` 表归属：** B-000 §5 要求该表，但 B-001～B-004 标题均未提及。R5 已在 B-003 中交付 `checkout_confirmation` 与 `checkout_confirmation_item`（行不加外键到 `cart_item`，车行之后可能被删）。如要拆成别的结构请在评审时说明。
- **V8 对手动冻结商品的处理：** B-000 §11 写 “原固定价冻结商品解除冻结、恢复在售”。实现为：交易冻结（`freeze_source=TRADE`）→ `ONLINE`；卖家手动冻结（`MANUAL`）→ `OFFLINE`/`offline_reason=MANUAL`，因为新模型没有冻结态，把卖家有意暂停的商品直接上架会改变其意图。如要按字面全部恢复在售，只需改 V8 中一条 UPDATE。
- **金额存储形式：** B-001 完成标准写 “十进制定点两位”，B-000 §5 写 “规范十进制 LONGTEXT”。已按 B-000 的 LONGTEXT + 两位小数格式 CHECK 实现，保证总额无上限。
- **V8 异常停止条件：** 固定价冻结且库存为 0、冻结来源未知、已关闭意向带有非本次的关闭原因，均会在任何变更前停止。
