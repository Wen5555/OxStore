# B-005 认证、归属与统一错误交接

2026-11-16，R1。基于R5 PR #22合并后的develop开发；本次不实现订单、收藏或购物车业务端点。

## 交付接口

- `JwtAuthFilter.INVALID_TOKEN`仅保存认证是否失败的请求属性，不保存原令牌。缺失客户令牌提示“请先登录”，无效或过期提示“请重新登录”；后台取消订单缺失/失效均提示“请先登录后台”。`/api/me/**`要求CUSTOMER，`/api/admin/**`要求SELLER。
- `CustomerAccess.requireCustomerId()`从安全上下文取得客户ID，不信任请求体身份；`requireOwner(ownerId)`校验车/收藏等单条归属；`requireOwners(ownerIds)`校验完整批次；`requireOrderOwner(ownerId)`使用订单专用拒绝提示。
- `ApiResponse.ok(message,data)`及`error(code,message,data)`保留固定提示和逐项错误；原方法继续兼容。`ApiBusinessException(status,code,message,data)`由全局处理器映射为HTTP状态及统一响应。
- CORS继续允许Authorization/Idempotency-Key/Content-Type；公开商品浏览不变。

## R4及后续R1服务的调用顺序

1. 先取服务端客户身份，读取全部选中行（含已删行归属记录），校验整个批次归属。
2. 按B-000顺序取得客户及业务行锁，并重验归属和状态；任何写操作前先完成所有权限校验。
3. 身份/角色/归属失败不继续处理合法子集。客户车/收藏越权40302“无权操作”，订单越权40302“无权操作该订单”。
4. 批量业务失败抛`ApiBusinessException`，例如`data={errors:[{cartItemId,productId,reason,message,...}]}`；不要逐个写入再逐个报错。前端按B-017接收data和原文，本次没有提前开发B-017。

缺失资源应由对应服务返回其契约错误；归属辅助类不代替数据库查找、行锁或事务。当前没有未来业务端点，不能把这些端点的端到端权限验收记为已通过。
