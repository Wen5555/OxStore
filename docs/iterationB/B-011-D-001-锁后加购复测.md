# B-011 / D-001：锁后加购的受控复测

核对时间：2026-11-22。代码基线：`develop@4dd570c`；R2测试代码：PR #32的源仓库`YanPeng240607/OxStore-@c6db1df`。此交付补齐可复现测试，D-001仍交R2独立复验后决定是否关闭。

## 结论与原因

目前没有复现“锁后新增量被清车误删”的生产缺陷。`CheckoutService`与`CartService`均先锁同一客户，B-000第8节和原[B-010～014交接](B-010-014-结算与订单交接.md)已约定：

- 确认后、提交取得锁前改量：确认摘要变化，返回40913，要求重新确认。
- 提交已取得锁后另端加购：加购等待下单提交；原车行被清理后，主动加购建新行，新增量保留。验收应检查同一商品的最终数量，不强制沿用旧`cartItemId`。

因此，“确认2件→串行改为3件→提交”属于前一种时序，返回409正确，不是后一种时序的失败证据。确认摘要包含数量，正常协议下锁定数量c等于确认数量q，单次提交中的`c-q>0`分支通常不能通过API构造；“订单2件+购物车1件”应在两次并发请求都完成后观察，而不是要求加购穿过仍持有的客户行锁。

R2的[B-040缺陷记录](https://github.com/YanPeng240607/OxStore-/blob/c6db1df5fe04f0ff4798d7d6c34de097020e7ead/docs/iterationB/B-040-验收执行/defect-log.md)描述了两轮受阻。[B-037脚本](https://github.com/YanPeng240607/OxStore-/blob/c6db1df5fe04f0ff4798d7d6c34de097020e7ead/docs/iterationB/B-037-验收执行/scripts/run_checks.py)的该检查执行上述串行改量，并将合取参数固定为`False`、结果固定为`FAIL`，所以仅更新后端再运行旧脚本也不会自动通过。PR #32当前源提交未包含独立的B-032运行包及其注入失败日志；已核对它包含的B032执行说明和通用线程栅栏脚本，客户端同时发请求/延迟发请求不能保证命中服务端已持锁的位置。

## 交付的测试钩子

新增`backend/src/test/java/com/team/shop/ChallengeBCheckoutPublicApiConcurrencyTest.java`，启动随机端口的真实Spring Boot服务，用Java HTTP客户端发送请求；仅账号、商品及令牌作为测试夹具准备，购物车修改、确认、提交、订单详情和购物车查询均走公开API。

控制点只存在于测试的Mockito spy中：在`ShopOrderRepository.saveAndFlush`调用前暂停。此时提交已经完成确认摘要核验，持有customer、product和cart行锁。真实写入仍通过仓库`save + flush`执行，不模拟成功、不直接改购物车或库存。另一个测试spy只记录加购已进入真实`CartService.add`，随后继续执行原方法。

用例`addAfterCheckoutLocksLeavesOneWhileOrderContainsTwo`顺序：

1. 购物车2件，确认；商品初始库存5，单价1.25。
2. 请求A提交，服务端达到已持锁控制点并暂停。
3. 请求B另端加购1件，确认它已进入服务，且在A释放前保持等待。
4. 释放A；A返回201，B返回200。
5. GET订单详情：仅一条明细、数量2、总额2.50；GET购物车：同商品新行数量1；库存3。
6. 重试A的原键：40909，购物车新增的1件不变。

对照用例`quantityChangedBeforeSubmitStillRequiresReconfirmation`保持R2串行时序：改量3后提交返回40913，车内3件、库存5、无订单。不得为通过AC2删除该校验或提前释放客户锁。

测试控制点不进入生产源码或打包JAR，不提供线上延迟开关、调试端点或旁路写入能力。无需启动原8083服务，也无需给现有后端注入断点；Maven会启动自己的随机端口服务。

## R2复测命令

仓库根目录，Java17+、Maven：

```sh
mvn -B -ntp -f backend/pom.xml -Dtest=ChallengeBCheckoutPublicApiConcurrencyTest test
```

默认H2。真实MySQL复测须先创建独立空测试库，执行`backend/src/main/resources/db/schema.sql`，然后运行：

```sh
mvn -B -ntp -f backend/pom.xml -Dtest=ChallengeBCheckoutPublicApiConcurrencyTest -Dchallengeb.jdbc.url=jdbc:mysql://127.0.0.1:33316/独立测试库 test
```

MySQL固定`ddl-auto=none`，默认root/空密码；通过`-Dchallengeb.jdbc.password=测试密码`覆盖密码。禁止对业务库执行这些会写夹具的测试。

运行成功后查看：

- `backend/target/d001-locked-add.json`：受控时序、HTTP状态、真实订单详情、余量车行和库存。
- `backend/target/d001-before-lock-change.json`：锁前改量返回40913的对照结果。
- `backend/target/surefire-reports/TEST-com.team.shop.ChallengeBCheckoutPublicApiConcurrencyTest.xml`：两项用例的JUnit结果；Maven非零退出时不得认定通过。

本次H2及独立MySQL 8.0.25的两项专项均通过，最新基线后端全量118项通过。R1的实际运行记录见[验证记录](../test/evidence/r1-challenge-b/d001-results.json)。R2可在自己的独立测试库运行此控制用例，或采用相同服务端控制点改造B-032；B-037中硬编码的失败检查须替换为两请求都完成后的实际断言。PR #32、B-040缺陷状态及最终验收结论由R2更新，本提交不代填通过结果。
