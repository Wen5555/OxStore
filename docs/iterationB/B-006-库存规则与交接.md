# B-006 库存维护与上下架交接

2026-11-16，R1。前置为已合并的R5 B-001/B-003及本次B-005。当前仅完成库存能力，不实现B-010～014、B-026或R4业务端点。

## 实现与调用

- `Product.stock`改为BigInteger，使用R5的BigIntegerStringConverter映射LONGTEXT；发布、库存编辑及详情响应同步传递精确十进制字符串，不经int/long/double或JS Number截断。
- 发布表单stock为字符串；PATCH只接受`{stock:"非负整数",category2Id:数字ID}`的所需子集，未知字段整次拒绝。负数、小数、科学计数法、前导零、空白、空串及JSON number不被自动转换/舍入，按契约提示且原数据不变。
- 人工改0自动下架；0改正仍下架，需手动上架；库存只表示剩余可售量，没有未完成订单扣减量下限。显式下架保存MANUAL；手动上架要求正库存并清除原因。
- 不再在库存编辑/上下架时清理旧意向或生成FAILED历史；R4 B-016负责关闭旧入口和只读归档。本次保留旧交易收尾，尤其拍卖中标success/fail；不能将旧方法用于新订单完成。
- 前端仅做本次类型变化必要适配：库存字符串类型/输入校验/上架判断，避免旧InputNumber舍入及旧错误映射覆盖原文；没有提前实现R3的购物车、订单、归档等页面任务。

## 给后续B-011/B-014的事务内库存方法

在同一Service事务中先按B-000顺序取得product行写锁，再调用：

```java
product.deductForOrder(snapshotQuantity, BusinessTime.now());
product.restoreForCancelledOrder(snapshotQuantity, BusinessTime.now());
```

`deductForOrder`只接受普通在售商品、正整数且库存足够；精确扣减，到0写OFFLINE/AUTO_ZERO。`restoreForCancelledOrder`按正整数相加；仅OFFLINE/AUTO_ZERO且回补为正数才恢复在售，MANUAL保持下架。人工库存调整与回补独立叠加。

这些方法不创建订单、不清车，也不自行实现订单幂等。B-014必须将“合法状态→CANCELLED”和库存回补放在同一事务，只在唯一成功状态变更后调用一次；不能重复调用再期待库存方法自行识别订单。新订单完成不调用这两个方法，也不调用旧markTradeSucceeded。
