# B-026 转收藏并发与幂等交接

负责人：R1。开发基线：`develop@48325f1`（PR #27，B-025已合并）。对应PB-B09、PB-B11、PB-B14、PB-B15；业务及返回格式继续遵循[B-000](B-000-公共开发约定.md)第9、10节与接口附件。

## 本次交付

在R4的`CartToFavoriteService`上完成并发与幂等接入验证，保留原有事务编排、客户行锁、墓碑与收藏操作代次，不另建转收藏服务。

- 请求指纹按去重后的购物车行ID数值升序计算。同一集合换序或重复ID属于同一请求；首次成功与错误明细仍按首次提交顺序返回。
- 兼容B-025已保存的顺序敏感指纹：从原回执中的已移动行与已跳过行还原完整选择集合，保持旧键可重试。同键增减任何行仍返回40916。
- 重试读取收藏代次时按商品ID升序加锁；常规重复40915，成功后发生独立取消则返回原成功结果，全程不再次写收藏或删车。
- 收藏写入、整行移车、墓碑和成功回执在同一事务中提交；Spring数据异常及直接JPA持久化异常均返回50001“操作失败，请重试”，并全部回滚。
- 下架逐项错误保留`productId/productName/reason`，`message`使用“商品已下架”，避免混用下单提示。

未改接口字段、数据库结构或前端业务实现，无需补跑数据库迁移。

## 并发结果约定

| 已先取得客户锁的操作 | 后续转收藏或其他操作的结果 |
|---|---|
| 先改量或加购，再转收藏 | 移走最新数量对应的整行；不检查数量是否超过库存，N按实际行数 |
| 先删行/清空，再转收藏 | 已消失行跳过，返回实际移动及跳过集合；全消失40005且不留成功回执 |
| 先转收藏，再取消收藏 | 两次操作分别成功，最终无收藏；旧键重试返回原成功结果，不恢复收藏 |
| 先转收藏，再主动加购 | 加购生成新行；重试旧转收藏请求不能删除新行 |
| 先转收藏，再修改旧行数量 | 返回40912，不重建旧行 |
| 同键并发转收藏 | 一次成功，其余40915；只提交一份业务变更与成功回执 |
| 新键并发选择有交集的行 | 后提交请求跳过已经移动的行，只移动自身仍存在的行 |

已有收藏保留原ID及收藏时间；移动不扣库存、不改变商品上下架状态、不创建订单。先校验整个批次归属，他人已删行也依据墓碑拒绝，不能因为行已不存在而跳过越权校验。商品锁等待后重新检查状态，下架导致整批拒绝。

## 验证与复验

新增`ChallengeBMoveConcurrencyIntegrationTest`，使用独立事务、多连接、闩锁控制交错顺序及三个写入位置的故障注入，共20项；H2和独立MySQL 8.0.25均通过。后端全量116项通过，前端构建通过。另在MySQL上实际停止并重新启动后端进程，验证原键常规重复、取消后的原结果回放及后来新车行保留。

可从仓库根目录运行（需Java17+及Maven）：

```sh
mvn -B -ntp -f backend/pom.xml clean verify
mvn -B -ntp -f backend/pom.xml -Dtest=ChallengeBMoveConcurrencyIntegrationTest test
```

MySQL复验须使用独立测试库，先执行`backend/src/main/resources/db/schema.sql`，再运行：

```sh
mvn -B -ntp -f backend/pom.xml -Dtest=ChallengeBMoveConcurrencyIntegrationTest -Dchallengeb.jdbc.url=jdbc:mysql://127.0.0.1:33316/独立测试库 test
```

MySQL测试默认用户root、空密码，使用`-Dchallengeb.jdbc.password=测试密码`覆盖；MySQL模式固定`ddl-auto=none`，不要对业务库运行测试。重启复验顺序为：转收藏成功→停止后端→使用同一库启动→原键40915→独立取消收藏→原键200且原结果不变→新加购→旧键再次重试后新车行仍在。
