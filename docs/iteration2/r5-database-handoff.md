九表主要设计、顾客认证、交易、类目、历史和大部分 API 已在上面的主分支基线中存在。本轮实际新增为：

## 接口协作边界

- 数据库约束负责用户名唯一、外键、库存非负、图片顺序/元数据、同商品交易唯一、终态历史等存储规则。
- 必须选二级类目、顾客鉴权、只允许编辑库存和类目、上传内容校验、富文本安全由相应应用服务执行；本轮用真实 API 与数据库结果联合验证，不用数据库列存在代替完整功能验收。
- 注册前口令意向保留在旧记录中，不创建顾客、不出现在账号购买历史；旧商品库存未知，迁移后设为0并下架，由卖家核实后补库存和上架。
- V4 已发布 SQL 保留一次性保护；重复升级入口负责跳过已完成的 V4。V5 可重复执行；任意中断后先核对结构和备份，不能用旧程序继续写新库。
- 历史商品名以快照为准，商品关联受外键保护，不级联清除历史。商品图按顺序第一张为主图；富文本插图不占九张商品图名额。
