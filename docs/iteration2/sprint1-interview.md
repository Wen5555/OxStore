- 访谈对象：SWBP 智能助教（需求机器人）
- 日期：2026-10-20（Asia/Shanghai）
- 原则：已裁定规则进本 Sprint；「待课程组确认」不实现，统一列在文末并采用临时边界
- 基线已知裁定：交易失败后商品恢复「在售」；队列按提交顺序递补；新队首不自动冻结，卖家发起交易时才冻结；重排无上限，由卖家每次确认

## 一、首轮访谈（已裁定）

### PB-01 多商品上架

**提问要点：** 在售上限；队列/冻结是否按商品；同人多队与同商品重复排；冻结互不影响；卖家并行多笔交易；发布必填字段。

**已裁定：**
1. 同时在售无上限。
2. 每件商品各自意向队列；冻结按商品；冻结一件不影响其他。
3. 冻结一件时，其他商品可浏览并提交意向。
4. 发布必填：名称、价格、类别、库存数量；选填：描述、图片（最多 9 张）。

**当时待确认（后见文末总表）：** 同一顾客多队/同商品重复排；卖家并行多笔交易。

### PB-02 库存与零库存自动下架

**已裁定：**
1. 库存为非负整数（≥0）；创建可为 0；为 0 立即自动下架。
2. 仅卖家标记「交易成功」时库存减 1；提交意向不预占。
3. 冻结与排队均不占库存。
4. 库存到 0：状态「已下架」，立即从可买列表与搜索消失。
5. 库存从 0 改回正数后须卖家手动重新上架。

**当时待确认：** 库存到 0 时队内未成交者如何处理。

### PB-03 浏览与搜索

**已裁定：**
1. 浏览/搜索默认仅「在售」；冻结不在列表，但可打开详情（只读，不可买、不可提交意向）。
2. 搜索匹配名称、描述（不含类别）；结果仅在售。
3. 未登录可浏览和搜索；提交意向需要注册登录。
4. 搜索结果展示：名称、价格、主图、所属类别；库存仅详情页展示。
5. 按二级类别筛选为可选表述（后被矛盾追问纠正为必做，见第三节）。

**当时待确认：** 分页条数、匹配方式、大小写、排序、空搜与无结果、浏览列表字段。

### PB-04 顾客注册与登录

**已裁定：**
1. 必填：用户名、密码、电话；默认交易地点选填。
2. 密码不少于 8 位。
3. 用户名唯一；用用户名登录；电话不作登录凭证。
4. 注册不需要电话验证码。

**当时待确认：** 格式/复杂度/电话唯一/地点取值/会话退出/失败锁定/改资料等。

### PB-05 登录后查看历史订单

**已裁定（首轮）：**
1. 至少包含有明确交易结果（成功/失败）的记录。
2. 每条至少：商品名称、下单时间、交易结果（成功/失败）、交易时间。
3. 时间倒序，支持分页。

**当时待确认：** 是否含中间态、扩展字段、每页条数、筛选搜索、详情、撤销、口令码迁移、下架后历史显示等（部分在矛盾追问中已闭环，见第三节）。

## 二、矛盾与未闭环清单（追问前）

整理自 PB-01～05 首轮答复与基线对照，摘要如下：

### A. 跨条目矛盾
1. **口令码 vs 登录：** PB-03 要求提交意向须登录；基线有口令码；PB-05 反问口令码是否还必要；注册前口令码意向是否进历史未定。
2. **类别 vs 二级分类：** PB-01 类别必填；PB-03 可按二级筛选；初稿曾延后二级分类，规则未对齐。
3. **主图 vs 图片选填：** 搜索要主图，图片却选填；无图展示未定。
4. **成交后库存仍 >0：** 扣库存规则与「成交即下架」单件老规矩冲突；回在售与队列递补未写清。
5. **历史终态 vs 中间态：** 字段偏向成功/失败；进行中意向买家端何处查看未闭环。

### B. 单条内部缺口（节选）
- PB-01：并行交易、同人多队待确认。
- PB-02：零库存时队内未成交处理待确认。
- PB-03：冻结详情入口、已下架详情、默认排序等未定。
- PB-04/05：大量格式与交互待确认（不纳入本轮追问范围，按「待确认不做/最简」）。

### C. 追问策略
只追矛盾与闭环；已标「待课程组确认」的条目不再单独追问其细则，但若该缺口导致无法闭环，要求给出本轮临时边界。

## 三、矛盾追问解答（机器人最终裁定）

### 问题1｜口令码 vs 登录
- **1.1 裁定：废除口令码。** 引入账号后不再需要口令码；不做并行、不做历史兼容（历史见 1.3）。
- **1.2 裁定：未登录不能提交意向。** 提交意向必须注册登录；口令码入口随废除从界面移除。
- **1.3 待课程组确认。** 注册前口令码意向是否/如何归到新账号，SRS 未写。  
  **临时边界：不迁移、不展示**——口令码时代意向本轮不进「历史下单记录」，不留实现。

### 问题2｜成交后库存仍 >0
- **2.1 裁定：回到「在售」。** 纠正「成交即下架」与库存的冲突：卖一件库存减 1；还有剩则继续在售；减到 0 才自动下架。「成交即下架」仅发生在卖出最后一件（库存刚好到 0）时。
- **2.2 裁定：** 队首成交后队列自动前移，下一位按先到先得成为新队首并继续排队；**不会自动冻结**；每笔交易由卖家主动发起，发起时才冻结当时新队首。
- **2.3 裁定：每单固定 1 件**，不允许一次买多件。库存表示「可卖几单」，不是单笔数量。

### 问题3｜类别
- **3.1 裁定：必须挂二级类目树才能发布**；单级文本/单级枚举不行；必须选到二级（一级→二级），为发布必填。
- **3.2 裁定：不能降级。** 「按二级类别筛选」与「二级类目数据」本轮都要做，砍掉任一都算缺需求。  
  → **范围影响：原延后的二级分类并入本 Sprint（见最终版待办 PB-03/US-03）。**

### 问题4｜主图 vs 图片选填
- **裁定：** 主图 = 第一张上传图片（不单设封面字段）。一张都没传时，列表/搜索/详情统一显示占位图；占位图即主图。

### 问题5｜冻结/下架详情入口
- **5.1 裁定：** 冻结商品不在列表和搜索；唯一合法入口是直链（详情 URL、分享链接等）；打开后只读，不可买、不可提交意向。
- **5.2 裁定：不允许。** 已下架（含库存 0 自动下架）商品，买家端打不开详情、不能提交意向，从买家端彻底退出。

### 问题6｜历史记录闭环
- **6.1 裁定：** 本轮历史只展示成功/失败终态；排队中、交易中、已撤销明确排除。
- **6.2 待课程组确认。** 进行中意向买家端本轮跟进入口，SRS 在废除口令码后未给替代页。  
  **临时边界：不展示**——进行中意向买家端本轮看不到；仅卖家后台「意向购买人列表」可见。
- **6.3 裁定：保留。** 历史一旦产生即留存；商品下架/删除不影响已有记录展示；商品名用下单时快照，不是「已删除」占位。

### 机器人总结
- 本轮待课程组确认共 2 条及临时边界：1.3 不迁移不展示；6.2 不展示。
- 其余 1.1、1.2、2.1–2.3、3.1、3.2、4、5.1、5.2、6.1、6.3 均为确定裁定，可写入验收标准。

## 四、访谈总结：相对于基线（迭代1 / V1）的需求划分

通过本次需求访谈与矛盾追问，相对于基线版本（迭代1 / V1：单卖家、单商品、匿名口令码），迭代2 的需求演进划分为以下四类：

### 1. 保留的需求
- 卖家预置账号登录、修改密码与后台管理。
- 买家按提交顺序排队，仅队首意向可被卖家发起交易。
- 卖家确认交易成功或失败；线下交钱交货（不做线上支付与物流）。
- 单卖家模式；不做购物车、一次购买多件（每单固定数量为 1）、多卖家及自动超时解冻。
- 卖家侧历史数据完整保留；商品名称等关键信息采用下单时快照留存。

### 2. 升级的需求
- **单活跃商品 → 多商品同时在售与独立队列：** 废除「同时仅一活跃商品」限制，允许多件商品同时在售，每件商品各自维护独立意向队列与冻结状态，互不阻塞。
- **成交即下架 → 库存扣减与状态流转：** 交易成功时库存减 1；扣减后库存 >0 则立即回到「在售」且队列自动前移，**新队首不自动冻结**（须卖家再次主动发起交易才冻结）；库存 =0 时才自动下架。
- **前台单品展示 → 列表浏览、二级类目筛选与关键词搜索：** 仅展示在售商品；支持按二级类目筛选与按名称/描述纯文本（富文本先剥标签）关键词搜索。
- **商品发布与受限编辑：** 发布必填扩展为名称、价格、二级类目、库存，选填多图与富文本描述；发布后仅允许原地修改库存与二级类目（改名称/价格/图文须手动下架后重新发布）。
- **冻结与下架详情访问边界：** 冻结不再包含卖家手动冻结，仅由卖家对该商品队首发起交易触发；冻结商品不在列表/搜索展示，仅可通过详情直链只读查看；已下架商品买家端不可打开详情。

### 3. 新增的需求
- **顾客注册与登录（PB-04）：** 用户名、密码（≥8位）、电话必填，默认交易地点选填；提交购买意向必须登录。
- **登录后买家历史订单（PB-05）：** 仅展示当前登录顾客本人的成功/失败终态记录（含商品名快照、下单时间、结果、交易时间），按时间倒序分页。
- **库存与零库存自动下架（PB-02）：** 支持设置非负整数库存，0 库存立即自动下架；库存从 0 改为正数后须手动上架才可恢复在售。
- **手动下架与手动上架（PB-06）：** 在售且无交易中意向时可手动下架；已下架且库存 >0 时可直接手动上架，不必重新发布。
- **多图展示与富文本描述（PB-07）：** 商品图选填最多 9 张（JPG/PNG，≤5MB），详情页支持按序查看全部商品图；描述支持换行、加粗、斜体、列表及插图（禁脚本）。
- **商家查看全部顾客与购买历史（PB-08）：** 卖家可查看全部已注册顾客列表，并按顾客只读查看其成功/失败终态购买历史。

### 4. 废除的需求
- **口令码整套机制：** 废除口令码生成、查询、修改、撤销及界面入口，不再提供口令码提交流程。
- **未登录匿名提交购买意向：** 未登录仅可浏览与搜索，不可提交购买意向。
- **「同时仅一活跃商品」限制：** 废除单商品在售上限。
- **卖家手动冻结/解冻商品：** 由交易触发冻结及手动上/下架替代。
- **交易失败后自动将新队首再次冻结：** 统一改为队列递补后保持在售，须卖家再次主动发起交易才冻结新队首。
- **注册前口令码意向迁移：** 采用临时边界，不迁移、不展示。

## 五、闭环后的本 Sprint 规则汇总（供最终版待办引用）

1. 多商品在售；每商品独立队列与冻结；每单 1 件；废除口令码；提交意向必须登录。
2. 成交成功库存减 1；>0 回在售并队列前移（不自动冻结）；=0 自动下架且买家不可开详情。
3. 二级类目必做（发布必选二级 + 买家二级筛选）；浏览/搜索仅在售；无图用占位图；冻结仅直链只读。
4. 注册：用户名/密码/电话必填，地点选填；用户名唯一且用于登录；密码≥8。
5. 历史仅成功/失败；倒序分页；快照保留；口令码历史不迁移；进行中意向买家端不展示。
