# T-000 公共开发约定

版本：迭代 2 Sprint 1  
适用仓库：`Wen5555/OxStore`  
更新时间：2026-10-28

本文件把迭代 2 的模块边界、接口、状态、错误码和协作规则固定在仓库内。需求验收以 `product-backlog.md` 和需求规格说明书为准。

## 1. 基线与模块边界

| 模块 | 目录 | 约定 |
| --- | --- | --- |
| 前端 | `frontend/src` | React + TypeScript；页面只能通过 `src/api` 调用后端 |
| 后端 | `backend/src/main/java/com/team/shop` | `controller → service → domain/entity/repository`；事务放在 Service |
| 数据库 | `backend/src/main/resources/db` | MySQL 8、InnoDB、utf8mb4；空库使用 `schema.sql`，旧库按迁移顺序执行脚本 |
| 自动化测试 | `backend/src/test`、`frontend/e2e` | 后端 JUnit/Spring HTTP 集成测试；前端 Playwright 流程测试 |

后端响应统一为 `{code, message, data}`。响应 DTO 与 Entity 分离。迭代 2 使用 `customer`、`seller`、`category`、`product`、`product_image`、`purchase_intent`、`order_history`、`trade_attempt` 和 `product_status_event`。

## 2. 迭代 2 接口清单

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 公开 | 顾客注册，用户名、密码、电话必填，地址可选 |
| POST | `/api/auth/login` | 公开 | 顾客登录并签发 `CUSTOMER` JWT |
| POST | `/api/admin/auth/login` | 公开 | 卖家登录并签发 `SELLER` JWT |
| GET | `/api/categories/tree` | 公开 | 获取一级到二级类目树 |
| GET | `/api/products` | 公开 | 在售商品分页、二级类目筛选、名称/描述纯文本搜索 |
| GET | `/api/products/{id}` | 公开 | 在线商品可购买；冻结商品只读；下架商品拒绝查看 |
| POST | `/api/products/{id}/intents` | CUSTOMER | 提交固定数量为 1 的购买意向 |
| GET | `/api/me/order-history` | CUSTOMER | 查询当前顾客成功/失败终态历史 |
| GET/POST/PATCH | `/api/admin/products...` | SELLER | 商品发布、库存/二级类目编辑、手动上下架 |
| GET/POST | `/api/admin/intents...` | SELLER | 按商品查看队列、开始交易、确认成功/失败 |
| GET | `/api/admin/customers...` | SELLER | 顾客列表和指定顾客的终态历史 |

商品发布字段为名称、价格、二级类目和库存，描述与商品图可选。商品图最多 9 张，格式为 JPG/PNG，单张不超过 5 MiB，第一张为主图。描述只保存清洗后的允许标签；列表不返回描述摘要。

## 3. 状态与错误码

### 3.1 状态

- 商品：`ONLINE`、`FROZEN`、`OFFLINE`。
- 意向：`QUEUING`、`IN_TRANSACTION`、`SUCCESS`、`FAILED`。
- 角色：`CUSTOMER`、`SELLER`。
- 只有 `SUCCESS` 扣减 1 件库存。库存变为 0 时商品下架并把剩余排队意向置为 `FAILED`。库存恢复为正数不会自动上架。
- 交易开始时只冻结当前商品队首；不同商品的队列和冻结互不影响。

### 3.2 错误码

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| 40001 | 400 | 参数校验失败 |
| 40002 | 400 | 请求体或参数格式错误 |
| 40003 | 400 | 分页参数错误 |
| 40101 | 401 | 未登录、令牌缺失或过期 |
| 40102 | 401 | 用户名或密码错误 |
| 40301 | 403 | 角色无权访问 |
| 40302 | 403 | 资源不属于当前用户 |
| 40401 | 404 | 商品不存在或已下架 |
| 40402 | 404 | 类目不存在 |
| 40403 | 404 | 意向不存在 |
| 40404 | 404 | 顾客不存在 |
| 40901 | 409 | 商品或意向状态不允许当前操作 |
| 40902 | 409 | 不是商品队首或已有交易中意向 |
| 40903 | 409 | 用户名已存在 |
| 40904 | 409 | 并发更新冲突 |
| 40905 | 409 | 库存不足或库存状态冲突 |
| 41301 | 413 | 图片超过 5 MiB |
| 41501 | 415 | 图片格式或内容不受支持 |
| 42201 | 422 | 富文本包含禁止内容 |

前端按 `code` 分支处理错误，不按中文消息判断业务逻辑。日志不能记录密码、JWT 原文或上传文件内容。

## 4. 分支、提交和 PR

- `main` 只保留可演示代码；任务开发使用 `feature/T-xxx-描述`、`fix/T-xxx-描述`、`test/T-xxx-描述` 或 `docs/T-xxx-描述` 分支。
- 提交格式：`<type>(<scope>): <动作> [T-xxx][PB-xx]`。`type` 使用 `feat`、`fix`、`test`、`refactor`、`docs`、`build` 或 `chore`。
- PR 标题使用 `[T-xxx][PB-xx] 动词开头的说明`，正文包含目标、影响模块、依赖、验证命令、How to demo 步骤和已知限制。
- 作者不能审核自己的 PR。认证、权限、数据库迁移、状态机、库存和接口字段变化至少需要一名其他成员审核。
- PR 合并后更新 Sprint 工作簿中的 PR 链接、状态和剩余工时。

## 5. 依赖顺序

`T-000 → T-001 → T-002/T-006 → T-003/T-007/T-010 → T-011/T-014/T-018/T-028 → T-029 → 验收测试 → T-022/T-023`。

前端可以依据本文件先用 Mock 开发，真实联调等待对应接口或数据结构合并。所有字段、状态和错误码变更先更新本文件，再同步 API 类型和测试。
