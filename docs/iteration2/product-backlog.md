## 1. 用户故事与验收标准

### US-01 / PB-01 多商品上架与按商品队列

**故事：** 作为卖家，我想同时维护多件在售商品，且每件商品有独立意向队列与冻结，以便并行售卖多件货。

**验收标准：**
1. 系统允许多件商品同时处于「在售」；无同时在售数量上限。
2. 每件在售商品各自维护一条意向队列；对 A 商品冻结不影响 B 商品浏览与提交意向。
3. 发布商品必填：名称、价格、二级类目（必须选到二级）、库存数量；选填：描述、图片（0～9 张，细则见 PB-07）。
4. 顾客提交购买意向必须已登录；界面无口令码入口；系统不再提供口令码提交流程。
5. 每笔交易固定数量为 1；不可一次购买多件。
6. 卖家发起交易时，才将「当时该商品队首」冻结进入交易；新队首不会自动冻结。
7. 仅当该商品当前无「交易中」意向时，方可对队首发起交易。

**本 Sprint 不做：** 同一顾客多队/同商品重复排的限制规则；卖家并行处理多个队首交易（跨商品并行冻结不在此列——按商品独立冻结已要求）。

### US-02 / PB-02 库存与自动下架

**故事：** 作为卖家，我想为每件商品设置库存，卖出后自动扣减，卖完自动下架，以便不用手工盯库存。

**验收标准：**
1. 库存为 ≥0 的整数；创建可为 0；创建时若为 0，立即处于「已下架」且买家端不可见、不可开详情。
2. 仅当卖家标记「交易成功」时，对应商品库存减 1；提交意向、排队、冻结均不改变库存。
3. 扣减后库存仍 >0：商品状态立即回到「在售」；该商品队列自动前移，下一位成为新队首并继续排队，但不自动冻结；需卖家再次主动发起交易才冻结新队首。
4. 扣减后库存 =0：商品变为「已下架」，立即从浏览列表与搜索结果消失；买家端不可打开详情、不可提交意向。
5. 卖家将库存从 0 改为正数后，不会自动上架，必须在后台手动重新上架后才可再次在售。
6. 库存到 0 自动下架时，队内未成交意向的处理见文末「待课程组确认」临时边界（与 PB-06 手动下架同一边界）。

### US-03 / PB-03 浏览、搜索与二级类目

**故事：** 作为买家，我可以通过浏览、二级类别筛选和关键词搜索找到在售商品；作为卖家，我发布商品时必须选择二级类目。

**验收标准：**
1. 存在可用的二级类目树（一级→二级）；发布商品时必须选择到二级类目，否则无法发布。
2. 买家端支持按二级类别筛选浏览；缺筛选或未实现二级类目均视为本条未完成。
3. 浏览列表与搜索结果仅包含「在售」商品；未登录可浏览与搜索。
4. 搜索匹配商品名称与描述的**纯文本**（描述若为富文本，须先剥标签再匹配）；**不匹配类别**。
5. 列表/搜索每条至少展示：名称、价格、主图、所属类别；**不展示描述摘要**；库存仅在详情页展示。
6. 主图为第一张**商品图**；若无商品图，列表/搜索/详情统一显示占位图（描述中的插图不得充当主图）。
7. 「已冻结」商品不出现在列表/搜索；买家仅可通过商品详情直链/分享链接打开，只读，不可买、不可提交意向。
8. 「已下架」商品买家端不可打开详情、不可提交意向。

**最简处理（待确认项不单列加分）：** 分页条数、搜索模糊/精确与大小写、默认排序、空关键词与无结果文案，按团队最简可运行方案实现。

### US-04 / PB-04 顾客注册与登录

**故事：** 作为新顾客，我想用用户名、密码和电话注册并登录，以便提交购买意向并查看历史订单。

**验收标准：**
1. 注册必填：用户名、密码、电话；默认交易地点选填。
2. 密码长度 ≥8；用户名全局唯一；重复用户名不可注册。
3. 使用用户名 + 密码登录；电话不作登录账号；注册无需验证码。
4. 未登录可浏览/搜索；未登录无法提交购买意向（无口令码旁路）。
5. 密码不以明文存储（哈希）。

**本 Sprint 不做：** 修改个人资料；失败次数锁定；电话唯一性等未裁定规则（按最简）。

---

### US-05 / PB-05 历史订单（终态）

**故事：** 作为已登录顾客，我想查看自己已有明确结果的历史订单，以便核对成交与失败记录。

**验收标准：**
1. 未登录访问历史订单时，引导登录。
2. 仅展示当前登录用户本人、且交易结果为成功或失败的记录；不展示排队中、交易中。
3. 每条至少含：商品名称（下单时快照）、下单时间、交易结果（成功/失败）、交易时间。
4. 按时间倒序；支持分页。
5. 商品后续下架或删除，不影响已有历史记录展示；商品名仍为快照。
6. 注册前口令码时代意向：本轮不迁移、不展示（见文末待确认）。
7. 进行中意向：买家端本轮不提供跟进入口；仅卖家后台按商品意向列表可见（见文末待确认）。

**本 Sprint 不做：** 历史筛选/搜索、单条详情页、在历史中撤销意向、扩展展示字段（价格/地点等）。

### US-06 / PB-06 手动下架与发布后字段编辑范围

**故事：** 作为卖家，我需要在库存仍大于 0 时主动下架商品，并明确发布后哪些字段还能改，以便纠错库存/类目，同时用下架重建来改名称、价格或图文。

**验收标准：**
1. 卖家后台必须提供「手动下架」：商品处于「在售」且该商品当前无交易中意向时，可转为「已下架」（库存仍 >0 的场景需要此能力；库存 =0 已由自动下架覆盖）。
2. 手动下架后：买家端立即不可见、不可打开详情、不可提交意向（与「已下架」一致）。
3. 手动下架后，若库存 >0，允许「手动上架」回到在售，**不必重新发布**。
4. 发布后**可编辑**字段仅限：库存数量、二级类目。
5. 发布后**不可编辑**字段：名称、价格、描述、图片（含商品图与描述插图）。
6. 若需变更名称或价格：路径为手动下架 → **重新发布**（新建商品）；不可原地修改。
7. 若需变更描述或图片：不可原地改；须下架后重建商品；主图仍等于商品图上传顺序的第一张。
8. 将库存从 0 改为正数后，商品仍保持已下架，须再执行手动上架（与 PB-02 一致）。
9. 手动下架（以及库存到 0 自动下架）时，队内未成交意向的处理见文末临时边界。

### US-07 / PB-07 多图展示与富文本描述

**故事：** 作为卖家，我想为商品上传多张图片并使用富文本描述；作为买家，我想在详情中看齐全部商品图并阅读格式化描述。

**验收标准：**

**多图**
1. 商品图选填，最多 9 张；格式仅 JPG/PNG；单张 ≤5MB；上传时做字段级校验并拒绝不合规文件（张数/大小/格式），不静默失败。
2. 详情页必须能查看该商品全部商品图（最多 9 张）；本轮验收为可按序前后切换看完即可，不要求缩略图条或自动轮播。
3. 主图 = 第一张商品图；列表/搜索仅展示主图；无商品图时列表/搜索/详情统一占位图。
4. 冻结商品直链只读详情中，多图查看交互与在售详情一致（仅只读、不可买、不可提交意向）。
5. 已下架商品买家端不可开详情，故不存在多图展示问题。
6. 本轮不提供商品图的改序、单张删除、单独指定主图（发布后图片不可编辑，见 PB-06）。

**富文本描述**
7. 描述选填；最低支持：换行、加粗、斜体、列表，以及**插图**；禁止：脚本/互动组件、复杂表格、公式；视频嵌入本轮不做（见文末）。
8. 空描述判定：先剥标签并去除空白后无可读文字 → 详情不展示描述区。
9. 描述中的插图与商品图**分开计数**，不占用「最多 9 张」名额；插图不得充当主图或占位图替代。
10. 插图格式/大小/张数见文末临时边界（最简：不单独设限、不做独立校验）。
11. 搜索时先剥标签，再按名称与描述纯文本匹配；类目不参与关键词搜索。
12. 列表/搜索卡片不展示描述摘要。

### US-08 / PB-08 商家查看全部顾客与购买历史

**故事：** 作为卖家，我想查看全部注册顾客，并进入某位顾客的购买历史，以便核对成交与失败记录。

**验收标准：**

**全部顾客**
1. 「全部顾客」= 全部已注册账号，含从未下单、从未提交意向的注册用户；不含未注册访客。
2. 列表每行至少展示：用户名、电话（商家可见完整电话）、默认交易地点、注册时间。
3. 默认交易地点未填时，列表该字段显示固定文案「未设置」。
4. 列表按注册时间倒序，支持分页；本轮不做搜索/筛选（见文末）。
5. 可从顾客进入其「购买历史」；本轮不做编辑/禁用/删除顾客账号。

**购买历史**
6. 商家侧购买历史仅含该顾客的成功 + 失败终态；不含排队中、交易中、已撤销（进行中仍只在「按商品意向队列」查看）。
7. 每条至少含：商品名（下单时快照）、下单时间、交易结果、交易时间；本轮不做价格、地点、数量字段（数量固定为 1）。
8. 商品下架或删除后，商家侧历史仍展示；商品名用快照，规则与买家端一致。
9. 本轮只要求「按顾客查看购买历史」；与「卖家历史商品」「按商品意向队列」三套视图相互独立，本轮不做互相跳转；不做全站订单总览。
10. 该购买历史只读；不可在此页确认成功/失败或取消意向（交易操作仍在既有交易流程中完成）。

## 2. Sprint 计划会建议拆分（任务粒度参考）

1. 数据模型：多商品、库存、二级类目、顾客账号、意向/订单终态快照、商品图与描述（富文本）
2. 废除口令码；提交意向改为登录校验
3. 卖家：发布/编辑（仅库存+类目）、手动上架、手动下架、按商品队列与冻结
4. 成交成功扣库存与状态机（回在售 / 自动下架）；下架时队内意向按临时边界作废为失败
5. 买家：浏览、二级筛选、搜索（剥标签）、详情多图按序查看、富文本只读展示
6. 注册登录会话；买家历史订单（成功/失败）
7. 卖家：顾客列表 + 按顾客购买历史（只读）
8. 联调与演示脚本（覆盖 US-01～08 主路径）

## 3. 完成的定义（DoD）建议
