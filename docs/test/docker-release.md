# OxStore Docker 交付版验证

版本：0.1.0-docker.1；日期：2026-10-12（Asia/Shanghai）。本次在远端 main `693f269` 的业务实现基础上完成容器打包，配置和自动验证程序随独立发布分支交付。

## 1. 构建与产物

后端在 Maven 3.9、Java 17 构建容器中执行 `mvn clean verify`：50 项 JUnit，失败、错误、跳过均为 0，JAR 打包成功。前端 Node.js 20 执行锁文件安装和 TypeScript/Vite 构建通过；前端大 chunk 提示属于构建警告，没有阻止构建。

交付包含前端、后端和 MySQL 8.0.46 的 Linux/amd64 镜像，Compose 配置、初始化脚本、schema/迁移、安装与构建手册，以及镜像中实际使用的 JAR 和前端静态产物。镜像身份、源码提交和校验值以随包 manifest.json / SHA256SUMS 为准。

构建时发现官方 npm 下载连接重置，改为沿用本机和锁文件已验证的 npmmirror 源；保持 TLS 验证。Docker 引擎中途重启造成两次构建 EOF，恢复后利用缓存重新构建成功，没有将中断作通过证据。

## 2. 真实容器检查

实测 Windows Docker Desktop Linux 引擎 29.8.2、Compose 5.5.1。脚本创建随机名称的独立项目、临时端口和全新数据卷，测试凭据仅在进程内存和后续录屏所需的库外临时文件中保留，不进入交付包。

`scripts/verify_docker_release.py` 的 23 项检查全部通过：

- 三服务健康、仅前端绑定本机端口、首页/后台登录/口令查询 SPA 路由。
- 空库初始化、后台未授权拦截、正确与错误密码登录。
- 5 MiB PNG 上传并经 Nginx 访问；超限拒绝；第二件活跃商品拒绝。
- 手动冻结/解冻、姓名和电话校验、三买家排队、修改及撤销、撤销码失效。
- 开始队首交易、交易中修改/手动解冻拒绝、失败重排保留原码/首次时间、自动递补、旧尝试确认拒绝。
- 成交下架、相关口令失效、历史意向/交易尝试/状态事件保留。
- 改密后重启应用，旧密码失效且完整记录保留；停止并重建三容器，数据库、图片、新密码和历史保留。

最终执行记录位于交付包 `evidence/docker-results.json`、`compose-operations.log`；JUnit XML 与构建日志也随包保存。初次验收脚本曾错误将容器内部暴露端口视为宿主机发布端口，并使用不符合完整 PNG 校验的夹具；修正检测和夹具后，从全新独立实例完整复测通过。未修改业务规则来迎合测试。

## 3. 实际浏览器录屏

Google Chrome / Playwright CLI 0.1.22 实际操作了容器入口：卖家登录、商品发布和图片上传、买家提交、队首开始交易、确认成功及完整历史展示。没有拦截或模拟 API。最后一轮从无活跃商品开始完整通过，保存 4 张真实截图及 WebM 视频；截图已读取检查。

公共复现模板是 `scripts/docker_ui_smoke.js`，启动器为 `verify_docker_ui.ps1`。随包 `evidence/ui-results.json`、`screenshots/`、`videos/docker-ui.webm` 对应本次执行。

## 4. 范围

本轮交付和证据针对容器构建、本机部署、指定业务流程及持久化。全量功能 UI 自动化、持续压测、ARM、目标 Linux 主机和正式公网部署未执行；课堂 PPT和教师评审意见不属于此次 Docker 包的完成项。既有数据库迁移没有对任何真实业务库执行，适用步骤保留在数据库手册中。

离线镜像重新导入后的启动与回归证据单独保存在交付包 `evidence/imported-smoke/`，以该目录实际结果为准，不把仅保存 tar 文件当作导入验收。
