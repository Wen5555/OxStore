## 1. 边界

| 项 | 约定 |
| --- | --- |
| 并存 | 售卖模式 `FIXED_PRICE`（普通在售，一口价 + 意向队列）与 `AUCTION` 并存，按商品二选一，默认 `FIXED_PRICE`。既有接口不传新字段时行为不变。 |
| 互斥 | 拍卖商品不能提交意向；普通商品不能出价。服务端在出价、意向、库存编辑和上下架入口重复校验。 |
| 不可切换 | 发布后 `sellingMode` 不可修改（实体 `updatable=false`，MySQL 触发器兜底）。 |
| 拍卖规则 | 英式增价、手工出价、库存固定 1；发布即开拍（无预约开拍）；截止时刻本身已不可出价。 |
| 中标履约 | 结拍生成一条普通 `purchase_intent`（`IN_TRANSACTION`）并冻结商品，之后用既有 `/api/admin/intents/{id}/success|fail` 收尾，不新增履约状态机。 |
| 技术 | SSE + 进程内事件 + `@Scheduled`；单实例。 |
| 不做 | PB-A05、类目/客群限制、保证金、代理出价、保留价、荷兰拍、撤回出价、匿名竞拍、WebSocket、Redis、站外通知、自动超时解冻/失败、重新开拍编排（流拍后重新发布新商品即可）。 |

## 2. 状态

| 对象 | 取值 | 说明 |
| --- | --- | --- |
| 商品售卖模式 `sellingMode` | `FIXED_PRICE` / `AUCTION` | 旧商品迁移后全部为 `FIXED_PRICE` |
| 拍卖场次 `auctionStatus` | `LIVE` → `ENDED_SOLD` 或 `ENDED_UNSOLD` | 只能单向结拍一次 |
| 商品 `status` | 沿用 `ONLINE/FROZEN/OFFLINE` | 竞拍中 `ONLINE`；中标后 `FROZEN`(TRADE)；流拍后 `OFFLINE` |
| 意向 `status` | 沿用 `QUEUING/IN_TRANSACTION/SUCCESS/FAILED` | 中标意向直接以 `IN_TRANSACTION` 创建，不进入排队 |
| 我的竞拍状态 `myStatus` | `NONE/LEADING/OUTBID/WON/LOST` | 仅已登录 CUSTOMER 的快照中出现；未参与为 `NONE` |

结拍裁定（截止后由扫描触发）：

| 场景 | 场次 | 商品 | 意向 | 提醒 |
| --- | --- | --- | --- | --- |
| 有有效出价 | `ENDED_SOLD`，成交价 = 当前价，中标人 = 领先者 | `FROZEN` / `TRADE`，写 `TRADE_STARTED` 事件 | 新建中标人的 `IN_TRANSACTION` 意向，`queue_seq=1`，并开启 `trade_attempt` | 卖家 `AUCTION_SOLD`，中标人 `AUCTION_WON` |
| 无有效出价 | `ENDED_UNSOLD` | `OFFLINE`，写 `AUCTION_UNSOLD` 事件 | 不创建 | 仅卖家 `AUCTION_UNSOLD` |

中标履约收尾：

- 成功：沿用 `POST /api/admin/intents/{id}/success`，库存 1→0、商品下架、写 `SUCCESS` 终态历史（已用真实 MySQL + API 验证，见数据库验证报告 W01）。
- 失败：沿用 `POST /api/admin/intents/{id}/fail`，拍卖商品只接受 `{"action":"DISCARD"}`；`REQUEUE` 返回 40908。失败后商品置 `OFFLINE`（不回到 `ONLINE`），写 `FAILED` 终态历史；卖家可重新发布。此分支由 P-A07 实现，需在 `TradeServiceImpl` 按 `product.isAuction()` 分支，普通商品语义不变。

## 3. 接口

时间字段均为 Asia/Shanghai 的 `yyyy-MM-ddTHH:mm:ss[.SSSSSS]`，与现有 `LocalDateTime` 序列化一致。金额为最多两位小数的十进制数（JSON number），范围 0.01～99999999.99。

### 3.1 发布（扩展既有接口）

`POST /api/admin/products`（SELLER，multipart，既有字段不变）新增表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `sellingMode` | 否 | `FIXED_PRICE`（默认）或 `AUCTION` |
| `startPrice` | 拍卖必填 | 起拍价 > 0；拍卖时忽略 `price`，商品 `price` 写为起拍价 |
| `minIncrement` | 拍卖必填 | 最小加价 > 0 |
| `endsAt` | 拍卖必填 | 截止时间，须晚于当前时间至少 60 秒、不晚于 30 天 |

拍卖模式下 `stock` 可不传；传入时只能为 1，否则 40001。普通模式下传入拍卖字段返回 40001。响应为既有 `ProductDetailResponse` 增加第 3.3 节字段。

拍卖商品的 `PATCH /api/admin/products/{id}`（库存/类目）只允许改类目，改库存返回 40908；`POST .../online` 返回 40908；竞拍中 `POST .../offline` 返回 40901。

### 3.2 列表与详情（扩展既有接口）

- `GET /api/products` 新增可选查询参数 `sellingMode`（缺省为全部）。
- `ProductSummaryResponse` 增加 `sellingMode`；为 `AUCTION` 时增加 `auction: {auctionStatus, currentPrice, nextMinBid, endsAt, bidCount}`，普通商品为 `null`。
- `ProductDetailResponse` 增加 `sellingMode` 与同上 `auction` 摘要；拍卖商品 `canPurchase` 恒为 `false`（前端据此隐藏意向入口），出价入口以快照 `canBid` 为准。

### 3.3 拍卖快照

`GET /api/products/{productId}/auction`（公开；带 CUSTOMER 令牌时补充个人字段）

```json
{
  "productId": 12, "productName": "二手显示器", "sellingMode": "AUCTION",
  "auctionStatus": "LIVE", "startPrice": 10.00, "minIncrement": 1.50,
  "currentPrice": 11.50, "nextMinBid": 13.00, "bidCount": 2,
  "endsAt": "2026-11-08T20:00:00", "settledAt": null, "serverTime": "2026-11-08T19:58:01.120",
  "leader": {"alias": "a***b"}, "lastBidSeq": 2,
  "recentBids": [{"bidSeq": 2, "amount": 11.50, "bidderAlias": "a***b", "bidAt": "2026-11-08T19:57:59.000"}],
  "canBid": true, "myStatus": "OUTBID"
}
```

- `currentPrice`/`leader` 在无出价时为 `null`；`recentBids` 最多 10 条，按 `bidSeq` 倒序。
- `alias` = 用户名首字符 + `***` + 末字符（单字符用户名为 `*`）。任何公开响应和 SSE 都不得出现顾客 ID、完整用户名、电话或地址。
- `canBid` 仅当已登录 CUSTOMER、`LIVE` 且 `serverTime < endsAt` 时为 `true`；未登录或 SELLER 为 `false`，且不返回 `myStatus`。
- 普通商品返回 40908；商品不存在或已下架返回 40401（已结拍的拍卖商品即使已下架仍可读快照，便于结果展示）。

### 3.4 出价

`POST /api/products/{productId}/auction/bids`（CUSTOMER）

请求 `{"amount": 13.00}`；成功 HTTP 201，`data` 为最新快照（同 3.3）外加 `bidSeq`。

校验顺序与错误码：

| 顺序 | 条件 | code / HTTP |
| --- | --- | --- |
| 1 | 未登录或令牌无效 | 40101 / 401 |
| 2 | 非 CUSTOMER（含卖家自出价） | 40301 / 403 |
| 3 | 金额缺失、≤0、超过两位小数或超上限 | 40001 / 400 |
| 4 | 商品不存在 | 40401 / 404 |
| 5 | 商品不是拍卖 | 40908 / 409 |
| 6 | 已结拍或 `now >= endsAt` | 40906 / 409 |
| 7 | 金额 < `nextMinBid` | 40907 / 409，`message` 中给出当前最低可出价，前端随后重拉快照 |
| 8 | 并发写冲突（唯一键或乐观锁） | 40904 / 409 |

服务端在同一事务内 `SELECT ... FOR UPDATE` 锁定场次行后判断 6、7，接受后写 `auction_bid` 并更新当前价/领先者/`bid_count`；无效出价不落库。卖家与顾客是两张账户表，卖家令牌角色为 SELLER，因此“卖家自出价”统一由第 2 步拒绝。

### 3.5 SSE

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/products/{productId}/auction/stream` | 公开；可带 CUSTOMER 令牌 | 单场次竞价流 |
| GET | `/api/me/auction-notifications/stream` | CUSTOMER | 本人结拍提醒流 |
| GET | `/api/admin/auction-notifications/stream` | SELLER | 卖家结拍提醒流 |

- `Content-Type: text/event-stream`。浏览器原生 `EventSource` 不能带 `Authorization` 头：匿名订阅用 `EventSource`；登录订阅用 `fetch` 读取流并带 `Authorization: Bearer`。不接受 URL 查询参数传令牌（避免令牌进入日志）。
- 每 15 秒发送注释心跳 `: ping`。客户端断开、超时（30 分钟）或发送失败时服务端清理订阅。
- 订阅后先推送一次 `snapshot` 事件（内容同 3.3）。断线重连一律：重拉快照 → 重新订阅；不支持 `Last-Event-ID` 回放。
- 客户端按 `bidSeq` 去重，丢弃 `bidSeq <= 已知 lastBidSeq` 的 `bid` 事件。
- 提醒流不允许订阅他人：路径只取令牌中的身份，没有用户 ID 参数；CUSTOMER 访问 admin 流返回 40301。

事件：

| event | id | data |
| --- | --- | --- |
| `snapshot` | `lastBidSeq` | 3.3 快照 |
| `bid` | `bidSeq` | `{productId, bidSeq, amount, currentPrice, nextMinBid, bidCount, leaderAlias, bidAt, youAreLeading?}` |
| `settled` | `"settled"` | `{productId, auctionStatus, finalPrice, winnerAlias, settledAt, youWon?}` |
| `notification` | 提醒 ID | 3.6 的单条提醒 |

带 `?` 的字段只在已登录 CUSTOMER 的连接中出现，按连接分别计算；公开连接只收到公开字段。事件在事务提交后发布（`@TransactionalEventListener(AFTER_COMMIT)`），回滚的出价不推送。

### 3.6 站内提醒与卖家管理

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/me/auction-notifications?page=&size=` | CUSTOMER | 本人提醒分页，最新在前，附 `unread` 数 |
| POST | `/api/me/auction-notifications/{id}/read` | CUSTOMER | 标记已读；他人提醒返回 40302 |
| GET | `/api/admin/auction-notifications?page=&size=` | SELLER | 卖家提醒分页 |
| POST | `/api/admin/auction-notifications/{id}/read` | SELLER | 标记已读 |
| GET | `/api/admin/auctions?status=&page=&size=` | SELLER | 拍卖管理列表，按截止时间倒序 |

提醒项：`{notificationId, auctionId, productId, type, productName, finalPrice, createdAt, readAt}`，`type` ∈ `AUCTION_SOLD/AUCTION_UNSOLD/AUCTION_WON`。

卖家拍卖管理项：`{productId, productName, auctionStatus, startPrice, currentPrice, bidCount, endsAt, settledAt, winnerAlias, winnerIntentId}`。`winnerIntentId` 非空时即履约入口，前端跳转到既有交易收尾操作。卖家后台可额外查看中标人联系电话用于线下交割（沿用既有队列接口对卖家展示电话的口径），公开接口不返回。

## 4. 错误码增量

在 T-000 §3.2 基础上新增，均为 HTTP 409：

| 错误码 | 含义 |
| --- | --- |
| 40906 | 拍卖已截止或已结拍，不能出价 |
| 40907 | 出价低于当前最低可出价 |
| 40908 | 售卖模式不支持该操作（拍卖商品提交意向/改库存/上架/REQUEUE，普通商品出价/读快照） |

## 5. 结拍调度

- `@Scheduled(fixedDelay = 5000)` 扫描 `status='LIVE' AND ends_at <= :now`，每批最多 50 个场次，逐个场次独立事务处理。
- `:now` 必须由应用传入 `BusinessTime.now()`；数据库会话时区不保证是 Asia/Shanghai（验证容器中 `NOW()` 为 UTC），SQL 中不得用 `NOW()` 判断截止。
- 幂等：事务内 `FOR UPDATE` 锁场次行并复查 `LIVE`；`winner_intent_id` 唯一、`(auction_id, notification_type)` 唯一、`@Version` 作为第二、三道保护。重复扫描或多次触发只会得到一次结拍和一组提醒。
- 演示可发布 1～2 分钟的短时拍卖；从截止到结拍提醒的延迟不超过一个扫描周期（约 5 秒）。
